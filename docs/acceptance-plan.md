The catalog-listed SDDs contain 533 distinct inventory case IDs across eleven capabilities and
fifteen documents: the original 353-case foundation, 79 platform companion cases, eleven task-policy
cases, 42 task-execution companion cases and the 48 household-entry cases published in PR #15.
The counts are derived from concrete observable scenarios and are minimums. The merged identity/storage
foundation has separate backend evidence in the [M1 audit](m1-acceptance-audit.md); the full product case
inventory is not complete.
Formatting, catalog metadata, branch readiness and working product acceptance are separate gates.

The first implementation is development tooling, with 85 executed tests recorded separately in the
[development guide](development.md). Its coverage measures the actual Python tooling and declarative
Node architecture policy. Later backend evidence and fictional framework-fixture evidence remain
separate from product UI/HA acceptance. The original product case floor
remains planned; passing tooling tests does not satisfy all product acceptance cases.

## From the first source file

Write meaningful behavior tests with each implementation. Enforce 100% supported first-party line, statement,
function and branch metrics separately for backend, frontend and integration code.
Do not mask untested paths with broad exclusions or count generated/third-party code as authored coverage.
Architectural rules, schema validation, permissions, replay/races and recovery are executable checks from the start.
Use deterministic clocks, IDs, bounded provider fakes and injected transaction failures.

The 2026-10-29 owner decisions add concrete cases for role-default verification, Ingress/host-context boundaries, configurable points allocation and actual-total reversals, optional external product lookup, recurrence anchored to actual work with per-task successor timing, and one automation engine with both editors. Its 45-case floor covers schema/editor round trips, permissions, durable waits/replay, partial recovery, resource/loop budgets and target/channel isolation. Case IDs, per-area budgets and reverse requirement mappings are regenerated together before running the unchanged original Copilot consistency functions.

The continued owner review specifies adjustable material quantities in the completion submission, stock shortfalls retained as pending consumption without negative stock, actual-work reporting periods, recurrence-edit previews and visible missed occurrences. Ledger cases additionally cover atomic performer allocations, closed completion cycles, already-spent-point reversals and negative-balance recovery. Receipt-retention and current-authorization cases prevent cleanup or replay from bypassing domain invariants.

The latest owner decisions add prerequisite-review preservation, durable disablement fencing and approved-reward funding holds, including admission/fulfillment/reversal races and restart. Identity cases cover all three administrator mappings, current HA-source revocation, configurable household profiles, member-override precedence and last-administrator safety. Repeated-time cases cover the first/second appearance and one-execution identity; UI/HA cases exercise the same policies without trusting a role label, transport credential or host hint as authority.

## CI Check contract

A project-owned workflow named CI Check runs for opened, reopened, synchronized and ready-for-review PR heads;
draft PRs still run tests. Do not use path filters to skip suites. Merge-queue validation is included if enabled.
Run backend/domain, frontend, HA contract/integration, migration/security, architecture, docs, localization,
browser E2E and both-target/channel packaging suites. The aggregate cannot pass if a required job is missing,
unexpectedly skipped, failed or cancelled. Record the exact checked revision and coverage reports.

PR code runs without publication credentials. Persistent self-hosted runner execution requires the repository's
trusted-PR policy; a skipped untrusted-fork run is not passing evidence. Provision toolchains in the job
that executes tests. The existing Copilot files remain unchanged.

## Real environment evidence
